# 司机身份以手机号为准，微信 openid 降为渠道绑定

## Status

accepted

## Context

服务端 `Driver` 以微信 `openid` 唯一识别司机，`phone` 目前可为空且不唯一；安卓端无法使用微信小程序的 `code2Session`，只能依赖手机号。若安卓端另建一套账号，同一司机在微信与安卓会变成两个 `Driver`，历史工单割裂。

## Decision

司机的稳定身份是手机号：`Driver.phone` 成为唯一标识，安卓端使用手机号 + 短信验证码登录；微信 `openid` 变为可选渠道绑定。同一手机号在任一渠道登录都指向同一个 `Driver`。

## Considered Options

- 微信开放平台登录：需企业认证与审核，未安装微信或拒绝授权的司机无法使用。
- 手机号 + 密码：无短信成本，但注册与找回密码体验差。
- 设备标识登录：仅演示可用，不可上线。

## Account merge rules

- 安卓短信验证通过即视为手机号所有权的充分证明，直接登录该手机号对应的 `Driver`，不转人工核验。
- 手机号不存在时创建新 `Driver`（`openid` 为空）。
- 微信账号绑定手机号时，若该手机号已属于另一个 `Driver`，执行合并：保留创建时间更早的账号，迁移救援工单、咨询工单、浏览痕迹，另一个账号标记为已合并（保留审计，不物理删除）。
- 既无手机号也无工单的微信空账号，合并时不保留。
- 两个账号都有工单时仍按「创建时间更早者为主」处理，合并动作写入操作流水。
- 任一账号被封禁时，合并后的账号保持封禁。
- `phone` 改为可空唯一（空字符串迁移为 `NULL`），避免多个未绑定手机号的司机违反唯一约束。

## Consequences

- 需要数据迁移：为已有司机补齐手机号、处理重复手机号、给 `phone` 加唯一约束。
- 需要短信服务商（签名报备）与发送频率限制；后续可接运营商一键登录。
- 微信老用户首次在安卓登录时，需明确「同手机号即同一账号」的合并规则与安全校验。
